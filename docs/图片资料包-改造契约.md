> 并行施工用。三个子智能体各改一个文件，**写入范围严格不相交**，全部按本契约对齐，
> 谁都不许改别人的文件。改前各自备份，改完 `node --check`。

## 0. 目标（一句话）

作者另外有一套生图系统，WriterX 里的「AI 配图」不需要了。把它改成**本地图片资料包管理器**：
登记本机任意图片文件夹为「资料包」，面板里能看到每个包存录了哪些图纸，选单张图或整个包，
放进书里当封面 / 人物立绘 / 场景插图；**图片包插进正文后轮番展示（轮播）**。
不再调用任何云端生图（`imageCreate` / `imageCatalog` / `imageBalance` / 生图余额 / 购买生图包 / 按张扣费全部去掉）。

## 2. 数据模型

### 2.1 资料包登记（书目录内，可见）
书目录 `<dir>/图片包/资料包.json`：
```json
{ "packs": [
  { "id": "p-xxxxxxxxxxxx", "name": "诸天·场景A", "root": "D:\\生图产出\\场景A",
    "note": "第 2 卷巷战", "updatedAt": 1730000000000 }
] }
```
- `root` = 本机任意绝对路径（作者另一套生图系统的输出目录）。
- `name` 显示名；`note` 备注；`id` 随机 12 位 hex。
- 文件不存在 / 解析失败 → 视为 `{packs:[]}`，**不报错、不覆盖**。

### 2.2 本地目录里的「图纸」
`root` 目录下的图片文件（扩展名白名单，大小写不敏感）：
`.jpg .jpeg .png .webp .gif .bmp`。子目录视为「分包」，可继续下钻。
单个图片字节上限 **8MB**。单目录最多列 **500** 项。

### 2.3 插图 entry 扩展（轮播帧）
现有 `.hermes/illustrations/index.json` 里一条插图 entry：
```js
{ id, anchor, caption, width, height, jobId, version, createdAt }
```
新增可选字段：
```js
frames: [ { id, version, width, height }, ... ]   // 每帧一张 .hermes/illustrations/<id>.jpg
```
- `id` 仍是主图（第一帧）的 id；`frames[0]` 可以与主图同 id，也可省略首帧（约定：**frames 只存「除主图之外的附加帧」**，面板/编辑器把 `[主图, ...frames]` 拼成完整序列轮播）。
- 单张图插入 = 不传 `frames`（长度 0 / 缺省），完全兼容旧数据。
- 图片包插入 = 传 `frames`（包内其余图，逐张已裁成 JPEG）。

## 3. Host 路由契约（包 B 实现，包 A 调用）

统一前缀 `/novel-shelf`，与现有 `serve(req,res,ctx)` 的 if 链同一位置追加分支。
沿用现有：`requireJson(req)`、`readBody(req, limit)`、`writeJson(res,status,body)`、`ShelfRouteError(msg,status)`、
`assertTrustedRequest`（loopback 围栏，别绕开）。

| 路由 | 方法 | 入参 | 返回 |
|:--|:--|:--|:--|
| `/novel-shelf/image-packs` | GET | `dir=<书目录>` | `{ packs: [...] }`（读 `图片包/资料包.json`，坏/缺→`{packs:[]}`） |
| `/novel-shelf/image-packs` | POST | `dir` + JSON `{packs:[...]}` | 写回该文件（先建 `图片包/` 目录），返回 `{ packs }` |
| `/novel-shelf/local-images` | GET | `root=<绝对路径>` `sub=<root 内相对子目录,可空>` | `{ entries:[{name, kind:'file'\|'dir', ext, path}], total }` |
| `/novel-shelf/local-image` | GET | `root` `path=<root 内相对路径>` | 图片原始字节，`content-type` 按扩展名，`x-content-type-options:nosniff` |

**护栏（B 必须实现，写进代码注释）**：
1. `root` 必须是绝对路径、且 `stat` 是目录；不存在→404。
2. `sub`/`path` 禁止 `..`、禁止绝对路径、禁止盘符；用 `realpath` 校验解析后仍落在 `root` 内（软链/ junction 逃出去一律 400）。
3. 图片扩展名白名单（§2.2）；其它文件不列、读时 400。
4. 单图 ≤ 8MB（读时按字节上限，超→413）。
5. 单目录最多 500 项。
6. `image-packs` 的 POST 写文件走书目录内 `safeTarget`/`confined`（沿用既有），不写书外。
7. 所有新增只读路由仍过 `assertTrustedRequest`（现有 serve 顶部已统一调用，确认没被绕开）。

**落书三路由复用 + 扩展**：
- `POST /novel-shelf/cover`、`portrait`、`illustration` 现有逻辑**保持不动**，A 仍按原样把本地图裁成 JPEG 后 POST。
- `POST /novel-shelf/illustration` 的 body 新增可选 `frames`：`[{data(base64 jpeg), width, height}, ...]`（已裁好的 JPEG，尺寸校验同主图 decodeJpeg，`长边≤1600`、与 width/height 一致）。
  - `writeIllustration` 把每帧另存 `.hermes/illustrations/<frameId>.jpg`（`frameId = randomBytes(6).toString('hex')`），
    和主图一起走 `updateIndex` 的 `stage`（先写好、旧图进回收站、失败回退，沿用既有 publishTogether/settle 语义）。
  - entry 写入 `frames:[{id,version,width,height}]`。
  - `replace=true` 换图时，旧 entry 的 frames 连同主图一起进回收站。
- `readIllustration(dir,id)`：除按 `entry.id` 找主图外，也要能在 `entry.frames` 里按 frame.id 找到并返回对应 `.jpg` 字节 + version。
- `listIllustrations(dir,file,anchor)`：返回的 items 每条带 `frames`（无则 `[]`）。
- `removeIllustration`：删图时把 frames 对应的 jpg 也进回收站。
- 兼容：老数据没有 frames，一律按「单张」处理，不报 409、不改老索引结构。

## 4. 落书契约（包 A 实现，调用包 B 的路由）

包 A 里已有 `placeImage(request)`（L1005 附近）：读 `jobId` 的 blob → 画布裁 JPEG → POST 三个 shelf 路由。
**改造要求**：新增一条「从本地资料包选图」的路径，但**尽量复用 placeImage 的裁剪代码**：

- 抽一个内部函数 `placeLocalImage({ bookDir, target, blob, frames? })`：
  入参是本地图 `Blob`（来自 `/local-image` fetch 的 `response.blob()`）与可选附加帧 Blob 数组。
  复用 `createImageBitmap` + `drawJpeg` + `topCrop`/`fitLongEdge`/`avatarRect` 的现有逻辑：
  - cover：`POST /novel-shelf/cover` `{data}`
  - portrait：`POST /novel-shelf/portrait` `{name,data,avatar,framing,replace}`
  - illustration：`POST /novel-shelf/illustration` `{name,anchor,caption,data,width,height,replace, frames?}`
  - `frames` = 附加帧各自裁成 `长边≤1600` 的 JPEG，组装 `[{data,width,height}]`。
  - 成功后 `notifyBookImages({bookDir,kind,...})`（沿用既有，触发书架重读）。
- **不再**调用 `callImageBridge("imageCreate"/"imageCatalog"/"imageBalance"/"imageSetPlacement"/"imageRead")`
  于面板主流程；`imageObjectUrl`/`imageBlob` 若仍被旧「本书的图」缩略图引用可保留兜底，但面板主视图改为读本地图。
