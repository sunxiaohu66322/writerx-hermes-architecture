## 2. 逐条核查（①–⑤）

### ① 联网搜索「会员专享」—— **改不了，也不该假装改**

| 事实 | 证据 |
|:--|:--|
| `searchProvider` **不是枚举**，任何字符串都收 | `@deepseek-ai/dsh-web/lib/index.js:48-49` `searchProvider: z.string(), fetchProvider: z.string()` |
| 选择规则：配置的 id 已注册且可用→用它；已配置但没注册→`WEB_PROVIDER_CONFIGURED_MISSING`；未配置且恰好一个可用→用它；多个→`AMBIGUOUS`；零个→`UNAVAILABLE` | 同上 `:33-39` |
| 本构建**只有一个** search provider：`writerx-hub` | `@writerx/dsh-web-search-hub/lib/provider.js:5` `WRITERX_HUB_PROVIDER_ID = "writerx-hub"`，`:84` `id = …` |
| **没有第二个 provider 可换**：`@deepseek-ai/dsh-web-search-deepseek` 这个包在本构建里不存在 | `dsh-base/cordis.patch.yml:478-481` 声明了该行；`node_modules\@deepseek-ai\` 下 `dsh-web*` 只有 `dsh-web / dsh-web-app / dsh-web-fetch-http / dsh-web-frontend / dsh-tool-web` |
| 「会员专享」是**服务端**拒绝，本地没有 feature 门 | `provider.js:144` `if (!response.ok || envelope.ok !== true) throw hubError(...)`；`dsh-entitlements/lib/policy.js:180-189` 里 `web_search` 只是键名白名单；`dsh-web-search-hub/lib/execution-context.js:176` 只给 `web_search` 补关联 id，不拦 |

⇒ **结论：配置层无法让 Hub 搜索免费。** 换 provider 这条路在本构建里是死路（没有可换的 provider），
所以本轮**没有改 `searchProvider`**（保持 `writerx-hub`）。
**等价替代**：`modsearch` 技能（已装，且经 `dsh-home\skills` junction 在 WriterX 技能列表里可见 ——
`F:\...\dsh-home\skills` → `I:\DSHHome\skills`，`modsearch/SKILL.md` 10,364 B）。
**边界**：这是"等价替代"，**不是**"解锁联网搜索"；Hub 那条路仍然要会员。

### ② `web_fetch` 缺失 —— provider 我能补，**工具行我补不了**

**三处 `fetch: false`，真正生效的是预设那两处**：

| 位置 | 内容 | 是否生效 |
|:--|:--|:--|
| `@writerx/dsh-hermes-app/cordis.patch.yml:108-115` | `- id: tool-web` `config: { search: true, fetch: false … }` | ❌ 不生效 —— 宿主行随后被 `dsh-web-app:555-556` `disabled: true` |
| `presets/create.patch.yml:230-236` | `- id: tool-web` `fetch: false` | ✅ 生效（创造模式） |
| `presets/writerx-assistant.patch.yml:344-350` | `- id: tool-web` `fetch: false` | ✅ 生效（写作助手） |

**为什么 profile 层打不到预设行** `[推断，有代码依据]`：`dsh-app-boot` 的 patch 索引是
"根树的 last-id-wins patch targets"，而预设行是**嵌套在预设声明里的**（`presets/*.patch.yml` 的 `- insert:` 深层缩进），
不在根树索引里。profile 的 `- id: tool-web` 只会命中根树那一行（已 disabled），打不到预设内那个。

**所以我做了能做的两件事**：
1. ✅ 把 `web.fetchProvider: http` 钉死（§1）—— 一旦工具被放开，provider 立刻可解析，不再依赖"恰好只有一个"的兜底。
   依据：`@deepseek-ai/dsh-web-fetch-http/lib/index.js:422` `LOCAL_FETCH_PROVIDER_ID = "http"`；该包行由 `dsh-base:483-484` 挂载，
   全树**没有任何** `disabled: true` 命中它。
2. ❌ **没有**去 `disabled: false` 宿主 `tool-web` —— 那会与预设里的同名工具行重复注册
   （`dsh-web-app:461-463` 注释原文："The Web app disables this host row and composes both tools per agent preset"）。
   **宁可少做，不做会撞的行。**

**真正的开启入口（需要用户先点一下）**：
产品自带 `wx_preset_copy`（`@writerx/dsh-hermes-presets/lib/preset-tools.js:27`），把内置预设复制成**用户预设**，
用户预设会渲染成 profile patch 的一行（`index.js:40 renderUserPresetRow`）—— **那一行才是我能安全编辑的对象**。
届时只改该行里的：

```yaml
- id: tool-web
  name: '@deepseek-ai/dsh-tool-web'
  config:
    fetch: true          # ← 由 false 改 true
    searchMaxQueries: 1
    searchMaxResults: 8
    searchTimeoutMs: 60000
```

**边界**：即使工具放开，抓页走的是 `dsh-web-fetch-http`（匿名公网 HTTP(S)，只接受公开地址、逐跳校验并钉住连接），
**与 Hub 会员无关**，但也**不等于**"能抓任何站"（内网/非公开地址会被拒）。
