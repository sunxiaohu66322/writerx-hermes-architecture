## 二、需求 1（最高优先）：顶部阶段条从 5 步改成"当前阶段 + 子步骤"

### 2.1 现状

位置：`client.js`，`//#region src/client/stage.ts` 起，到 `stage_bar_module_css_default` 结束，约 **34494–34635 行**。

现在是固定的五步：

```js
const STAGES = ["立项", "大纲", "推演", "正文", "润色"];
```

渲染成标题旁一条：`立项 › 大纲 › 推演 › 正文 › 润色`

每个 `li` 有 `data-state`，取值三种：

| data-state | 含义 | 现在的样式 |
|---|---|---|
| `reached` | 书里已有这一阶段的材料 | 正常色 |
| `ahead` | 还没到 | 透明度 .7 |
| `current` | 本对话正在做这个阶段 | 主色 + 浅色底 + 圆角胶囊 + 加粗 |

"走到哪"的判定函数：

```js
function stageSteps(book, skill) {
    const current = skillStage(skill);              // 本对话正在用哪个写作技能
    const found = {
        ...book.planned ? { 立项: "已立项" } : {},
        ...book.outlines > 0 ? { 大纲: `大纲 ${book.outlines} 份` } : {},
        ...book.prose === void 0 ? {} : { 正文: `正文 ${book.prose}` }
    };
    const furthest = Math.max(...);
    // 返回 [{stage, state, note}]
}
```

证据来源是目录树：

```js
function bookEvidence(tree) {
    const outline = tree.root.children.find(n => n.kind === "dir" && n.name === "大纲");
    const { stats } = tree;   // stats.chapters / stats.words / stats.stories
    return { planned: true, outlines: outline?.files ?? 0, prose: ... };
}
```

### 2.2 问题

1. **五个阶段的颗粒度太粗。** 作者不知道"开书"里面走到第几步——是刚定了题材，还是已经写完全书故事。作者原话：「我们现在到底走到哪一步了？我要知道。」
2. **只有三级状态，没有"跳过"和"卡住"。** 这本书`大纲/` 是空的，界面却显示"推演""正文"已经是 reached（因为已经有 5 章正文），视觉上像是走到最后了，实际卡在开书第 5 步。
3. **"当前阶段"靠本对话加载了哪个技能来判断。** 但作者可能一天不说话、或者在本对话里干了三件事，高亮就会错。**不能用"本对话在干什么"当进度，要用"这本书实际有什么"。**

### 2.3 要改成什么样

**核心改变：一行显示当前大阶段，后面跟这一大阶段的子步骤；子步骤按真实进度逐格点亮。**

```
开书  ①定位 ②故事核 ③世界 ④人物 ⑤全书故事 ⑥分卷 ⑦自检 ⑧黄金三章
        ●      ◐       ◐      ◐      ○        ○      ○      ◐
```

- 当前所处的大阶段**加粗**（沿用现在的胶囊高亮样式即可）
- 子步骤用符号区分：`●` 做完、`◐` 做了一半、`○` 没做、`⊘` 跳过（作者主动跳的）
- **当前子步骤**用主色加粗，其余灰
- 悬停每一步，`title` 显示：这一步做什么 + 现在的依据（比如「大纲/ 目录 0 个文件」）

### 2.4 完整十八步（照抄，不要自己缩减）

### 2.5 状态判定：改读状态文件，不要猜

**不要再从目录树猜。** 加一个真相源文件：

```
<书目录>\01-项目状态.md
```

这个文件由写作助手维护（格式见第六节）。前端只做两件事：

1. `api.loadTree()` 之后，额外读一次 `<书目录>\01-项目状态.md`
2. 解析里面的一行进度声明，用它决定 18 个格子的状态

**约定格式**（助手保证按此写，不要改这个格式）：

```markdown
<!-- WRITERX-PROGRESS v1
stage: 开书
step: 5
steps: positioning=done, core=half, world=half, cast=half, story=todo, volumes=todo, selfcheck=todo, golden3=half
updated: 2026-11-13T18:00:00
-->
```

- `stage`：三大阶段之一，`开书` / `每章` / `收尾`
- `step`：当前子步骤编号 1–18
- `steps`：18 个键的状态，取值 `done` / `half` / `todo` / `skip`
- `updated`：ISO 时间

**文件不存在或解析失败时**：退回现在的目录树判定逻辑（保留原逻辑作为 fallback，不要删），并给整条阶段条加 `data-state="unknown"`，悬停显示「还没有进度文件」。

这样即使助手忘了写，界面也不会白屏或撒谎。

### 2.6 空间不够的处理

18 格一行放不下（现有 CSS `@container (width<=760px)` 已经是直接隐藏整条了）。

要求：

- 只显示**当前大阶段**的 6–8 个子步骤，另外两个大阶段用 `「开书 · 大纲 · 收尾」` 三个可点的小字切换
- `<760px` 时保留现有行为（隐藏整条），不要改成折行
- 子步骤之间分隔符沿用现有的 `›`，不要换成新符号

## 三、需求 2：候选与采用的闸门

### 3.1 现状

助手写正文直接 `write` 到 `chapters\000N_标题.md`，作者没有"这章我认不认"的环节。曾发生过：助手写的第 1 章被另一个 AI 的版本覆盖，作者完全不知道。

### 3.2 要加什么

1. 书目录下新增 `待确认\` 目录
2. 助手写完先落 `待确认\000N_标题.md`
3. 界面在章节列表里给 `待确认\` 下的文件加标识（例如文件名前一个 `?` 角标，或多个小圆点），悬停说明「候选稿，未采用」
4. 提供两个操作：
   - **采用** → 移到 `chapters\000N_标题.md`（若已存在同名，先备份旧的到 `.versions\`）
   - **退回** → 移到 `待确认\退回\`（不删）
5. 采用后，若 `<书目录>\01-项目状态.md` 存在，把 `step` 改成 14（回写），提示助手去做回写

**注意**：这两个操作是本项目新增的写文件动作，必须走现有的备份机制（`.versions\` 或同级 `.bak-时间-说明`），不要裸覆盖。

## 四、需求 3：取证包抽词改成按问题取

### 4.1 现状

后端 `index.js` 里有 `gatherEvidence(bookDir, ch)`，实现是：从本章要求里抽 20 个词 → 按"全书出现≥2 次"过滤 → 拿剩下的词去全文搜段 → 落 `<书目录>\story\工序台\chNNNN\02-装配材料.md`。

第 6 章实跑产物在：`G:\Users\Administrator\Documents\WriterX\作品\诸天1.0-...\story\工序台\ch0006\02-装配材料.md`（16.4 KB）

### 4.2 实测出的毛病（必须改）

抽出来的 9 个词，命中段数如下：

| 词 | 命中段数 | 问题 |
|---|---|---|
| 时代 | 12 | 是设定文件的**小标题**，取出来全是背景说明 |
| 器物 | 7 | 同上 |
| 场景 | 6 | 同上 |
| 景图南 | 6 | 人名，几乎每章都出现，等于没过滤 |
| 主管 | 6 | 同上 |
| 礼拜三 | 6 | 时间线词，碰运气 |
| 这一栏 | 3 | 句子碎片 |
| **推荐人** | **3** | ✅ 只有这个是本章真正要用的 |

即：**按"词"去搜，搜到的只是"提过这个词的段落"，不是"这一章要用的答案"。** 51 段里能用的不到 10 段。

### 4.3 改成什么样

**从按词搜，改成按"本章要回答的问题"取。**

输入不变（本章细纲／创作要求），但处理换成三步：

1. **抽问题**，不抽词。从本章要求里认出三类东西：
   - **人物**：本章出场的人名（去人物库里比对，命中才算）
   - **线索**：本章要推进的那条线（如「推荐人」「内招」「房租」），来自细纲或上一章章末钩子
   - **待答**：本章要交代但前面没写清的事
2. **按问题取段**：
   - 人物 → 取这个人最近的 2–3 次出场段（不是全篇都取）
   - 线索 → 取全书所有提到这条线索的原段
   - 待答 → 取上一章末尾 + `pending_hooks.md` 里对应那条的原文
3. **砍掉标题词**：设定文件里的 `##` 小标题（如「时代」「器物」「场景」「地理」）一律不进搜索词表

**硬要求**：
- 每条仍然标 `来源文件 · 第N段`，可回查
- 找不到写「未命中」，**不许编**
- 目标：总段数从 51 降到 **15–25 段**，但**每一段都能用上**
- 抽词／问题清单要留在产物里，让作者能看出"它为什么取这些"
