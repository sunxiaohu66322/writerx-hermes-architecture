## ③ 检索机制

代码：`memory-retrieval.js:12-94`（`retrieveMemorySelection`）、`local-search.js:60-97`（`search`/`migrate`）。
参数：scope=`story-memory`（官方）/`story-ledger`（B4 原型，独立库表）；排名 `bm25(retrieval_documents_fts,5.0,1.0)` 即 **title=5.0 / body=1.0**，`ORDER BY rank ASC`、`score=-rank`；候选 top-**32**（引擎上限 200）；查询为分词去重前 64 token 各加引号 `OR` 连接；分词 = NFKC + `Intl.Segmenter(word)` + 相邻单汉字 bigram + 连字符兜回；`replaceScope` 按 `content_hash`(sha256 hex) 跳过未变行、`BEGIN IMMEDIATE`。语义层 = `composer.selectMemoryCandidates`（LLM 在 32 条里挑，`temperature 0.1`，装配 `runner.js:2925`），**不是向量库**。

**章号过滤**：官方 FTS 查询本身不按章过滤（章号在 `metadata_json`），过滤在二次筛选——摘要 `chapter < chapterNumber`、近 3 章硬给 + BM25 只买 1 个召回名额、按章升序输出（`:256-278`）；伏笔 ±5 章窗口 + stale 回收；事实靠谓语白名单基础分 20/18/16/14/12/10 与 `score>=14` 保底、top-4。原型才把章号写进 SQL：B4 `d.chapter <= asOfChapter` 防未来泄漏；B3 `effectiveFacts` 区间 `valid_from<=N AND (valid_until IS NULL OR valid_until>=N)`（与 A 层差 1 章，两库不合并）。

**四类走哪**：人物 → Markdown `设定\角色卡.md`/单人卡经界面 `read` 进上下文（InkOS 侧 `kind=character` 仅 1 条未定位生产者）；剧情/摘要 → `chapter_summaries.md`/`state/chapter_summaries.json` → `chapter_summaries` 表 → `kind=chapter-summary`；伏笔 → **`pending_hooks.md`/`state/hooks.json` 为权威，明确不走 DB 判定**（`:32-35` 注释：DB 只存子集，丢 `coreHook/promoted/dependencies`），`hooks` 表仅留痕；状态/事实 → `current_state.md`/`state/current_state.json` → `facts` 表 + `kind=fact`，靠谓语白名单与分数地板进 prompt、不靠检索命中。

## ④ 账本 / FTS5 接口

**bridge 五动作**（`inkos-bridge.mjs` `ops["longform"]` `:956-1001`，别名 `longform/longform-contract/longform-commit`）：`contract`（零模型、不改状态）、`extract`（规则抽取 explicit/inferred/ambiguous）、`commit`（读官方 state 生成四工件→算哈希→幂等入账，写 `ledger.db`）、`reconcile`（只读比对 `canon_manifest`/`ledger_chapters`，产出 `ledger_ahead`/`consistent`，即双真值检测器）、`show`（六表倒出）。`commit` 三闸门：正文存在 → 正史已提交（`CANON_NOT_COMMITTED` 硬拦）→ `(chapter,artifact_hash)` 两级幂等。

**原型导出（只读 `readOnly:true`）**：`ledger-context.js` → `renderLedgerBlock(bookDir,{asOfChapter,maxChars=1800})`（缺库/无条目返回 `null`，一字不加）、`hasLedger`(`false`)、`loadLedgerRaw`(空数组)、`effectiveFacts`（区间+按 `subject|predicate|object` 去重留 `valid_from` 最大）、`ledgerPath`/`LEDGER_REL`/`BLOCK_HEADING`；`openLedgerReadOnly` 先 `existsSync` 再开，不存在返回 `null` **绝不建库**，模块内零 `readFile` 正文、零金额正则。`ledger-fts.js` → `SCOPE`/`INDEX_REL`/`DEFAULT_LIMIT=5`、`tokenizeSearchText`/`buildMatchQuery`（与官方同实现）、`mapEventsToDocuments`（纯函数）、`rebuildLedgerIndex`/`searchLedgerEvents`/`renderLedgerEventBlock`/`dropLedgerIndex`；查询路径只读、索引不存在返回空数组不建库；结果作**附加块拼接**，不参与 `story-memory` 排序。

**幂等/降级（B6 实回显）**：`rebuild #1 {indexed:3,skipped:0}` → `#2 {indexed:0,skipped:3}`；hits=2、`engine=sqlite-fts5-bm25#story-ledger`、每条带章号/证据句/source；`asOfChapter=1` 第 2 章事件零泄漏；`drop` 后 hits=0、重建恢复 2。缺库：`available:false`、块返 `null`、不建索引库。坑：`node:sqlite` 读 TEXT 在首个 NUL 截断，曾致索引永不幂等 → 改 sha256 hex。**三条红线（B2）**：`memory.db` 一字节不写；`ledger.db` 只 `SELECT`；原型唯一新建文件是 `ledger-index.db`。

## ⑥ 已知限制

1. **本版账本写入不可靠**（B6 §3 两项高危 `[实测不通过]`）：`-ForceRecommit` 不是替换而是**追加**第二个 `chapter_commit`，`add` 无条件累加 → 余额翻倍；`ledger_ops` **不进 artifact 哈希**，只改金额/键/操作而其余不变被判 `skipped_duplicate`，改动静默丢失且返回 `status:ok`。内联 JSON → `ops={}` → 落 0 笔账仍返回 `ok`+`applied_entries>0`（那是 facts 不是账目）；唯一可信判据 = `balances` + 直接 SELECT。
2. **第一版只读投影，不做双真值**：B3/B4 全只读、缺库零增量、不写回 `story/*.md`、`memory.db` 一字节不写；`ledger.db` 是可选补充源而非第二真值；正史权威仍是 md/json，两库 `valid_until` 差 1 章、`facts` 不合并。
3. **B 层账本没接进 InkOS 读取面**：`planning-materials.js:111-118` 的 8 个 md 输入清单不含 `longform/`，也不含 `memory.db`；`memory.db` 是加速索引，删了能由 md 重建。
4. **两条静默降级**（B1/B5）：`runner.js:2646-2651` 同步失败只 `logWarn`，不写 manifest、不中断、调用方无字段可查；`memory-retrieval.js:68-69` 语义选择器返空数组 `[]` 为 truthy → 空 Set → 所有 BM25 分数被清空（抛错反而正确退回纯 BM25）。均表现为「模型像忘了前面的事」。
5. **词法边界**：`两万八` ↔ `28000` 永不互命中（bigram 无完整三元组、ICU 切碎三字人名、跨词假 bigram 噪声）→ 金额必须走 B3 确定性注入；向量检索经 `B-向量检索必要性评估` 否掉，不引入 embedding。
