# linkos-novel 长篇小说工作流

## 当前版本状态（2026-11-09 实测，先读这一节）

**这套流程分两半：手艺层能用，账本层不能用。** 独立验收已用源码与现场实测钉死，不要跳过这一节直接照第 10–12 步走，会走空。

| 层 | 状态 | 范围 |
|:--|:--:|:--|
| 开书七步 / 排细纲 / 写一章 / 采用 / 落正文 | ✅ 可照做 | 文件自足，能一直写到完本 |
| 改稿 / 去AI味 / 卷末和完本 | ✅ 可照做 | 同上 |
| **推正史** | ❌ **任何书都失败** | 见下「为什么」 |
| **记账本（金额/数量）** | ❌ **静默失效** | 不报错，但记 0 笔 |
| **账本投影到下一章** | ⚠️ 命令能跑，无内容 | 上游断了，投影为空 |

**推正史为什么不行（三层，任一层单独就够钉死）：**
1. 桥接 `recover` 不带章号时拼出 `inkos write sync <book> --json`，只有一个位置参数；引擎 `sync` 签名是 `[book-id] <chapter>`，单参数被当章号 → `parseInt("书id")=NaN` → 抛 `Expected chapter number`。
2. 就算补上章号，引擎 `_resyncChapterArtifactsLocked`（`runner.js:1870`）要求该章已在 `chapters/index.json`——而它**不扫目录**，手写的新章不在里面 → `Chapter N not found`。
3. 还要求 `story/snapshots/<N-1>/current_state.md` 与 `pending_hooks.md` 存在。**快照只有引擎跑过才产出**：新建书 0 个，手写书连 `story/state/` 都没有 → `baseline snapshot N-1 is unavailable`。

**记账本为什么静默失效：** `lfCommitChapter` 只认**文件路径**（`opsFile && existsSync(opsFile) ? jread(opsFile) : {}`）。传内联 JSON → `ops={}` → 零笔 → 仍返回 `status: ok`。**所以「命令成功」不代表「记进去了」，这一条必须记牢。**

**当前正确的用法（唯一可执行状态）：**
- 想稳定写正文：**只用手艺层**（第 1–9 步），账本层整段跳过。此时它等价于 `axu-novel`，但多了一套更细的档案与自检。
- 想要机器账本：**先在桥接补 `sync` 章号 + 摸清 `index.json`/`snapshot` 的生成条件**，否则不要开这一层。开了就是假账。

**下面所有讲账本、推正史、投影的章节，按「设计说明 / 待修复后的目标形态」读，不要当「现在能照做」读。** 修好后本节会更新。

这套流程用一套 Markdown 档案，加一本本机的机器账本，把一本长篇从想法写到完本。它要解决两件事：**AI 只记得这一次对话里的东西**，以及**同一个事实被记成两个互相打架的版本**。前者靠把书存在对话外面；后者靠两条：同一件事只在一个地方记当前值，再加一本能自动对账的机器账本。

下面说的“你”就是作者本人。档案里的记录也按你的口吻写。

## 四条不能破的约定

这四条是整套流程能长期跑下去的根基，每一步都要守住：

1. **你没认可的东西，不算数。** 每一章先算候选，放进 `待确认/`。你说采用、或交回你自己改好的最终稿，才存进 `正文/`、才推正史、才记账本、才回写记录。讨论过但没定下的想法，不写成正式设定。原因：一旦把没采用的情节记进档案和账本，后面每一章都会建立在一个不存在的事实上，越写越错。
2. **开书一步一停。** 开书阶段每做完一步，把结果给你看，你确认了再做下一步。不要一口气从构思跑到正文。原因：故事是你的，方向错了，后面每一步都白做。遇到方向上的选择（卖点、选哪个方案、核心人物、核心设定），停下来等你本人回复；你请别人代你审的，代审的回复不算这类确认，代审只按你定的方向检查成败以外的质量。开书阶段永远不上批量。
3. **做没做完，照实说。** 没跑完的步骤、没查到的资料、没能做的检查，直接告诉你，在 `01-项目状态.md` 里记真实进度。不能把“写的时候注意过了”当成“已经改过了”。账本没提交成功就说没提交成功，不许说“已经记进去了”。
4. **账本可以重建，正文和设定不能有第二个真值。** 机器账本（`story/longform/ledger.db`）是**派生投影**，删了能按 `story/longform/commits/NNN.json` 重放重建，所以它错了可以重建，不必心疼。但 `正文/` 与设定／人物／伏笔这几份文件**不能有两份互相打架的版本**——一份在 md 里、一份在账本里，谁对不上就必须当场查正文定案，不能让两边各自当真。这条和第一、二条是同一个思想：**权威状态只在一个地方**。

## 这本书有两份档案，先认清哪份是真值

第一次接手一本书，先分清这两样东西，混着用就一定出矛盾：

| | 纸档案（Markdown） | 机器账本（InkOS 书目录） |
|:--|:--|:--|
| 在哪 | 你的小说文件夹，`01-项目状态.md` 那一套 | `books/<书id>/` 下面 |
| 谁读 | 你和 AI 读，**换对话能接上的唯一依据** | 引擎读；`story/state/*.json` 是正史 |
| 改动方式 | 逐条编辑 | 只通过 bridge 的命令改，**不手改 json、不手改 db** |
| 出错会怎样 | 记错就是记错，下一章跟着错 | 有闸门：账本超前直接拒，状态降级挡下一章 |

- **正史只有一份**：`books/<书id>/story/state/*.json`。`story/longform/ledger.db` 是它的派生投影（`projection_role: derived_read_models`），**不要为了“对不上”去删账本**，先 reconcile 看差在哪。
- **两份档案的对应关系只有一张表**，写在 `06-账本对接.md` 里。哪份 md 对哪个 json、哪个字段是权威，全在那。
- **你拍板，机器记账。** 你认了哪一版 → 落正文 → 推正史 → 记账本 → 投影回下一章 → 回写五份记录。顺序不能颠倒，颠倒了就会出现“账本里记着一件没采用的事”。

**两条防串台规则（不写就一定会串）：**

- `待确认/` 与 `正文/` 是**唯一**的稿件归属判据。`books/<书id>/chapters/` 只是引擎的副本，**不许拿它判断采用没采用**。
- 同一章只允许一条路径产出稿子：手艺，或引擎。**两路都跑 = 两套候选互相污染**，后面分不清哪份是底稿。

**一句必须先知道的事实**：本机引擎是**单模型串完全程**（Plan → Compose → Write → 审 → 结算），并不存在“A 写 B 审”的双模型协作。所以走引擎时不要指望“换个模型审一遍”，审就是同一个模型在审。

## 现在在哪个阶段

接手一本书，第一个动作是读 `01-项目状态.md`，然后跑三条只读命令看机器那侧的真实状态（都是零成本）：

```powershell
$B = "G:\Users\Administrator\Documents\deepseek-harness\default-workspace\inkos-bridge\inkos-bridge.mjs"
node "$B" -Op doctor                          # 模型链路／项目／书／技法库／账本五路探活
node "$B" -Op books                           # 全部作品与 id，书 id 从这里取，不要猜
node "$B" -Op state -Book <书id>              # 写到第几章、开场伏笔、降级章、快照
```

`-Op state` 直接给出四样关键值：`last_applied_chapter`（正史推进到第几章）、`open_hooks`（还没收的伏笔）、`degraded`（哪些章状态降级）、`snapshots`（可回滚到哪几章）。**先看它，再决定下一步做什么**，不先体检就动手是瞎猜。

按 `01-项目状态.md` 的“当前阶段”分四路走：

- **开书** → 见“开书：七步”。没有档案就先按 `references/档案.md` 建档，不要直接在正文里开写。
- **写正文** → 见“写正文：每一章同一个循环”，细节读 `references/写一章.md`。
- **卷末** → 见“一卷写完，和完本”，细节读 `references/卷末和完本.md`。
- **完本** → 只做归档与收尾核对，不开新章。

文件夹里已经是别的结构的旧档案（3.0 版、`追踪/` 目录、或别的工作流的档案），按 `references/档案.md` 的“从旧档案迁入”处理：**先只读盘点，给你一份对照方案，你同意了才动。**

## 看榜、读同类书时守住这几条

- **只读你能正常看到的。** 公开榜单、简介、免费试读，你自己买了或交给我的章节。不绕过付费和登录，不批量下载。
- **只学方法。** 节奏、结构、怎么放设定、对白怎么带脾气。不搬句子，不搬具体的人物关系、事件安排和独特细节。
- **别人的原文不存进档案。** 档案里只记书名、读了哪部分、学到了什么，用你自己的话写。
- **撞了就重新设计，不靠换名换词躲。** 和某本书的具体情节、人物关系撞了，告诉你，把这一块重新想。常见题材和套路（重生、升级、师徒）撞了没关系，不为这个改你的方向。

## 开书：七步，每步做完给你看

每一步做什么、怎么检查、成果存哪，都在 `references/开书.md` 里，做到哪一步读哪一节。每步的成果存进档案并更新 `01-项目状态.md` 的开书进度，这样换对话也能从上次停下的地方接上。

1. **弄清你想写什么**：一次问一两个具体问题，了解你喜欢的人物、情节和阅读感受，还有不想写什么。访谈后做一次脑洞体检：卖点打不打架、读者会追问的前提、强弱和数量、金手指能不能一句话说清、书名能不能兑现，有问题直接提，你来定。
2. **看看读者在看什么**（能联网才做，你可以跳过）。
3. **三个故事方案**：讲成故事给你挑，再按你的意见改到满意，然后确认卖点。
4. **世界、人物和全书故事**：搭世界与主要人物，讲完整本书，整理阶段和节奏，汇总成故事框架。
5. **开书自检**：沿具体事件检查前提、因果、信息揭示、前三章看点、人物主动性和长期变化。
6. **黄金三章**：找最抓人的那一下、设计开头、排前三章细纲，问你要一份参照（你自己的文字，或你挑的一章），再按“写一章”的循环一章一章写，每章交你之前做一次冷读。前三章采用以后，从中总结出这本书的写法，补进 `00-写作规则.md`。
7. **第一卷分卷纲和接下来几章的细纲**：读 `references/排细纲.md`。细纲排完按九个问题检查，写“检查结果”，交你确认。

**开书第一步之前，先建目录骨架（只建骨架，内容由我们填）。**

```powershell
node "$B" -Op book-create --name <书名> --id <书id> --genre <题材> --approve
```

**这条命令只会落盘建目录和三份占位文件（各几十字节），不会替你填设定。** 设定、人物、大纲这些实质内容，全部由 `references/开书.md` 一步步和你一起填进 md，再同步进机器那侧。别指望 `book-create` 把书写出来——它是个空壳。想让它调模型生成（`--via-cli`）也行，那是付费的，且生成的方向你未必认，开书阶段仍要逐项过一遍。

**每一步额外做一件事，这是本 Skill 与纯手艺流程的差别**：把这一步定下来的方向同时写进机器那侧，让引擎也认这个方向（不写的话，将来切引擎跑会走偏）。

```powershell
node "$B" -Op intent-set -Book <书id> -Text "<长期意图：卖点、主角要什么、这本书要写成什么样>" --approve
node "$B" -Op focus-set  -Book <书id> -Text "<近期重点：当前卷目标、这一批细纲要兑现什么>" --approve
```

**可选前置：把拆书产物里的技法灌进来。** 你手上有拆书成果时（`<拆书成果目录>\` 里有世界观、角色卡、文风、伏笔），可以检索技法卡并注入本章重点：

```powershell
node "$B" -Op craft -Query "父子 矛盾 钱 对白" -Limit 8                    # 零成本检索
node "$B" -Op craft-inject -Book <书id> -Query "..." --approve              # 注入 current_focus.md
```

两条注意：① 技法库状态是 `ok_degraded`，**召回会混进不相关的卡**，混了就换词重检，别现场调参，更别把卡当作文写；② 注入只进摘要与一份 `story/references/craft-*.md`，**只借结构与技法，不搬原句**。

有现成材料（自己定好了设定、写好了前三章）就从缺的那一步开始，不要求从头走。已有材料先读、先核对，不要推翻重来。

## 写正文：每一章同一个循环

### 两种写章方式，默认走手艺

| | 手艺（默认） | 引擎 |
|:--|:--|:--|
| 谁写 | 我按本书规则、处境卡、参照写 | InkOS 的 Plan→Compose→Write→审→结算 串起来写 |
| 花多少 | 0 | **每章 4–14 万 token，等 10–20 分钟** |
| 腔调由谁定 | 你的写作规则 + 参照 + 处境卡 | InkOS 自己的 rules，**上面那三样插不进去** |
| 落点 | `正文/第NNN章.md` | `books/<id>/chapters/`，状态 `ready-for-review` |
| 采用怎么做 | 你点头 → 落正文 → 推正史 → `longform commit` | 你点头 → `-Op review-approve`（结算真值，调模型） |

**默认永远走手艺。** 理由是你的原话——“填好资料就能直接生成文章”，要的是随时能用、不心疼。手艺路径边际成本近乎零，处境卡、参照、去 AI 味这一整套都在，钱一分不花。

**要走引擎，必须你亲口喊。** 你说“用引擎跑这一章”（或“用引擎写”“让引擎写这章”）才走，我不主动提、不主动跑。**喊了以后我先回你一句再动手**：预计这一章花多少 token（4–14 万）、大概等多久（10–20 分钟）、**腔调会脱离本书规则**。你点头才跑：

```powershell
node "$B" -Op compose -Book <书id> --approve      # 组装本章上下文（少量 token）
node "$B" -Op write   -Book <书id> -Count 1 --approve
```

跑的时候**不要催**：一章 10–20 分钟是正常，bridge 超时已设 2400 秒；看到 `streaming` 日志行就是还在写。它是**多段模型调用、成本按段累加**，不是一个 prompt。写完我读稿、交你候选，不要直接算采用——引擎写完只到 `ready-for-review`，**不进正史**，等你点头才 `review-approve`。

### 步进档：默认逐章

- **默认一章一交。** 每章写完自检一次，交你一个候选，你点头我再动档案和账本。这是候选制能成立的前提——候选制要你逐章看得见。
- **批量要你喊。** 你说“连写 3 章”“连写 5 章”才批量，**最多 5 章**，不设更大的档。你没喊就一章一章来。
- **批量时中间各章仍逐个进 `待确认/`，不自动进 `正文/`。** 采用还是逐章点头，只是不用每章都停下来等一次。
- **批量有一条必须提前告诉你的代价**：这批里第 N 章被你推翻，第 N+1 到 N+k 就是建立在一个不存在的事实上的，要整段重写。所以批量只在细纲已确认、方向稳的时候用；开书阶段不批量。

### 循环（每章一模一样，13 步）

```text
1  恢复状态        读项目状态；回写停在“进行中”先补完
2  闸门自检        细纲覆盖到本章没有？检查过没有？你确认没有？三者缺一 → 停下排细纲
                   上一章 state-degraded？→ 先修，不写新章
3  写前合同        longform -Action contract -Chapter N（零成本）→ 读一遍，检查里面有没有「卷纲未写本章」
4  只读本章资料    按细纲抽实体清单 → 查人物／现状／伏笔／设定／资源／废弃设定 + 上一章结尾
                   + memory -Query 兜底 + 「上一章的账本投影」（见第 12 步留下的那段）
5  转处境卡        细纲 → 时间地点／从哪到哪／谁在场各要什么怕什么／谁知什么／定下的结果／最值得展开的场戏
                   存 待确认/第NNN章-处境卡.md，不给你看
6  读参照一口气写完   读完就写，中间不翻规则；写到处境卡定的停止处就停
7  自检一次        去AI味五问；保留有效表达；守住不能改的
8  连读            上一章结尾连到本章结尾，核事实／知情／时空／持物／对白承接
9  交候选          存 v2-候选；项目状态登记“当前唯一候选”；只交章号章名正文
10 你采用 → 落正文 → 推正史   存 正文/第NNN章.md；**复制一份进 books/<id>/chapters/** 再跑
                   -Op recover（write sync）；正史推不到本章账本一定被拒——所以必须用 -Op state 验
11 记账本          longform -Action extract -Chapter N → -Action commit（金额必须结构化，不许猜）
12 投影回下一章     把账本里的当前事实／余额／未收伏笔，写成受管区块塞回 current_focus.md
                   ← 这一步不做，下一章读不到，账本就白记了
13 回写五份记录 → 留档 → 推进   人物现状／伏笔／时间线／设定／资源 → 旧稿归 待确认/已处理/
                   标完成、推进一章、看两件事：细纲剩不到三章 / 是不是本卷最后一章
```

**第 3、4 步里的两条零成本命令**（`contract` 把本章要求固定成文件；`memory` 按词检索既有事实与章节片段，在 `story/` 与 `chapters/` 里扫，不用读整本书）：

```powershell
node "$B" -Op longform -Book <书id> -Action contract -Chapter <N>
node "$B" -Op memory   -Book <书id> -Query "人名 地点 物件 伏笔词" -Limit 8
```

**第 3 步必须真读一遍合同**：`contract` 从卷纲里找含「第 N 章」的那段，**找不到也不会拦你**，会写一句「（卷纲未写本章）」照常出文件。一份看起来正常、其实空洞的合同照样能骗过后面每一步。

**第 12 步是本 Skill 的核心动作**，机器不会自己做：

```powershell
node "$B" -Op intent -Book <书id>                        # 先取当前 current_focus.md 原文
node "$B" -Op longform -Book <书id> -Action show         # 账本当前事实／余额／未收伏笔
node "$B" -Op focus-set -Book <书id> -Text "<原内容去掉旧投影块> + <新投影块>" --approve
```

投影块用受管区块 `<!-- ledger-projection ch=N -->` 包起来，重复投影只替换这一块、不叠加。块内固定四样：**在册事实**（只取仍生效的）、**资源余额**（照抄 show 的结果，不许自己算）、**未回收伏笔**（hookId + 一句话）、**挂起待确认**（没有就写“无”）。完整格式与边界见 `references/账本.md`。

**每一步的展开、处境卡模板、正史怎么推、回写中断怎么接、走引擎时每一步的具体命令，全在 `references/写一章.md`。写之前读它。**

## 一卷写完，和完本

一卷的最后一章采用、回写完成以后，进入卷末，读 `references/卷末和完本.md`：检查这一卷许给读者的事、写卷总结并把旧记录归档、对照全书故事框架、排下一卷的分卷纲和细纲。每一步给你看。最后一卷写到结局前，先把没收的伏笔列给你定，写完标“完本”。

**卷末用机器那侧的真实数据核一遍“许给读者的事兑现了没有”**，比人肉翻记录可靠：

```powershell
node "$B" -Op state    -Book <书id>                     # open_hooks = 还开着的伏笔；snapshots = 可回滚到哪几章
node "$B" -Op longform -Book <书id> -Action show
```

`open_hooks` 里每一条都要在卷末有个说法：这一卷收了、留到下一卷、或有意不收。**账本里开着的伏笔，正文里不能说已经收过。**

## 改稿

你指出某一段别扭、某一处对不上，或者想做一次冷读检查，读 `references/改稿.md`。要点：先找到问题的根因再改，只改你让改的范围，改完连读前后文。你认可了某次改法，问你要不要把它写进 `00-写作规则.md`，以后不再犯。

改稿**不改已采用的正文事实**。真要改事实（人物的过去、事件先后、数量、伏笔结局），先跟你确认，改完要把受影响的记录和账本一起改——这是唯一允许动账本内容的情形，且必须说明改了哪几处。

## 出问题了怎么查

按症状查判据和动作。这张表每一条都对应真实错误码，不要凭感觉猜。

| 症状 | 判据 | 动作 |
|:--|:--|:--|
| 1 秒返回、0 token | 报 `Latest chapter N is state-degraded` | `-Op recover -Book <书id> -Chapter N --approve`。**只重建真值文件，不重写正文**；不许用“重写整章”绕，且只允许修最新一章 |
| 返回 `status: approval_required`、`executed: false` | 缺 `--approve` | **不是故障，是“已请示未执行”**。等你同意后带 `--approve` 重发 |
| 报 `CANON_NOT_COMMITTED` | 这一章正史还没推进到（闸门只认 `manifest.lastAppliedChapter`，不认 md） | 顺序是：采用稿**先进 `books/<id>/chapters/`** → `-Op recover -Book <书id> --approve`（走 `write sync`，重建真值文件与索引，**可能计费**）→ `-Op state` 验 `last_applied_chapter` 是否等于本章号 → 对上才 commit。没对上按 `degraded` 列表处置，见 `references/写一章.md` 第十节 |
| 报 `chapter_already_committed` | 同章内容变了又想重记 | 确认内容真变了再加 `-ForceRecommit`；没变就别重记 |
| 报 `BOOK_NOT_FOUND` | 书 id 错了或没建 | `-Op books` 取真实 id，**不要猜、不要假设“就那一本”** |
| 报 `ENGINE_INTERNAL_ERROR` | 引擎自身缺陷 | 看返回的 `data.raw`；模型档需要 `use_legacy_chat_completions=true`（本机构建上的必崩点） |
| 写章很久没动静 | 有 `streaming` 日志行 | **等着**，10–20 分钟正常，超时 2400 秒 |
| 账本 `ledger_ahead` 非空、`consistent: false` | 账本超前于正史 | `-Op longform -Action reconcile` 看差在哪几章，**不要删账硬凑** |
| 技法召回不准、混进不相关的卡 | `craft` 是 `ok_degraded` | 已知问题（旧库字段质量参差）。**别现场调参，先写正文**；换词重检也只做一次 |
| 两份记录互相矛盾 | 同一件事记了两处 | 回查已采用的正文，**以正文为准**，再把错的那处改掉并说明 |
| 下一章写着写着和账本对不上 | 第 12 步没做或投影块旧 | 补投影，再往下一章走 |

## 本版不做、将来可接

这两个能力 LinkOS 里有真链路，但**要么需要常驻服务、要么需要人工前置**，所以第一版不接进主线。写在这里是让你知道它们没消失，也写清接的条件——**不是“接上就能自动跑”**：

- **场景推理器（9136）**：链路是真的（`_场景连接.py` 把施工图写进 `story/focus/chNN.brief.md` 与 `chNN.focus.md` → `_切章.py N` 复制成 `story/brief.md` 与 `story/current_focus.md` → planner 读得到）。但它有两个前置：① 必须先有 `books/<id>/_章场景配置.json`（**目前全库 0 个**，缺了直接报错退出）；② **只有人在 9181 界面点按钮才会触发**，批量写章脚本根本不调它。所以第一版的替代做法是：你自己点一次，再让我按“写一章”写——**等于多一道人工**。等这两条被自动化覆盖，再补 `references/场景调制.md`。
- **小说资料版本库**：第一版用两样东西顶着——`-Op state` 里的 `snapshots`（引擎侧逐章快照，每章一份真值文件副本）、`待确认/` 留旧稿 + `正文/` 只放采用版。**要“整卷退回”这种粒度，本版做不到**，只能手工把 `正文/` 和记录改回去。等版本库服务能读写再补。

不接的代价要说清：**本版没有“一键回滚到第 N 卷”**。要退，靠手工改文件加 `snapshots` 复原，会慢。

- `references/去AI味.md`：写完初稿以后的一次自检，五个问题，每个附错例。
- `references/账本.md`：`longform` 四个子动作、三档判定、金额规则、幂等、对账、降级修复、投影格式。**只在第 11、12 步用。**
- `references/卷末和完本.md`：一卷写完怎么收、最后一卷怎么收尾。
- `references/改稿.md`：局部改稿、怎么找根因、按反馈更新规则、冷读。
- `assets/写作规则-默认版.md`：建档时复制成项目里的 `00-写作规则.md`。
- `assets/档案模板/`：建档时复制的其他文件模板，含 `06-账本对接.md`。

## 什么时候停下来问你

- 要改变核心设定、世界规则、重要人物的命运，或者推翻已经采用的正文。
- 不清楚你采用的是哪一版（几份候选并存，或你刚提过修改意见）。
- 资料之间互相矛盾，查了已采用的正文还是判断不了。

## 什么时候该用 axu-novel

两套 skill 同一个形态、同一套档案，别打架，按需要挑：

| 你的情况 | 用哪个 |
|:--|:--|
| 只想写，不要账本、不想装依赖、不想付任何费 | `axu-novel`（成熟、纯 Markdown） |
| 要账本能查“记录和正文对不上”（`reconcile`） | **本 Skill** |
| 要引擎写整章（愿意付 token 换速度） | **本 Skill** |
| 要“这一卷许给读者的事兑现了没有”有机器数据兜底 | **本 Skill** |
| 要账本的实体归一、资源确定性计算、传闻过期 | **本 Skill** |
| 开书、写章、去 AI 味这些纯手艺活 | 两套都能，`axu-novel` 更轻 |

**同一本书可以两套混用，前提是档案结构一致**——本 Skill 的档案文件名完全迁就 `axu-novel` 的命名，就是为了这个。但**同一章不要两套各写一遍**。
